# 后台改造完整分类需求

> **执行总原则：只改后台与后端数据链路，不改前端。** 所有需求必须按分类逐项完成，禁止自行理解为改造前端页面、前端功能、路由、组件、样式、文案、交互或接口契约。

---

## A 类：不可触碰的前端边界

1. 不允许修改前端任何代码、页面、组件、路由、样式、文案、按钮、交互、功能逻辑、接口地址、接口字段、请求参数、响应格式或前端缓存逻辑。
2. 不允许新增、删除、隐藏、重排或重写前端模块。
3. 不允许以“前端需要配合”为理由要求我再修改前端。
4. 前端只继续使用现有代码、现有接口、现有字段和现有读取逻辑。
5. 后台自动化可以推送数据给前端，但推送的数据必须完全兼容前端现有数据表、接口、字段、类型、状态和值域。

**目标：前端一行代码不动，但由于后台持续写入或推送不同数据，前端每天展示的内容自然不同。**

---

## B 类：模块管理完善

将“模块管理”定位为**前端现有模块的后台数据控制台**，不是前端 UI 控制台。请完整盘点并录入前端已存在的全部数据模块，包括但不限于：首页区块、栏目列表、新闻流、榜单、推荐位、搜索数据、详情关联内容、公告数据、下载数据及其他数据入口。

每个模块必须建立唯一模块 ID，并保存以下字段：

| 字段分类 | 必填字段 |
|---|---|
| 基础信息 | 模块 ID、模块名称、模块说明、模块分组、模块分类、负责人、备注 |
| 前端映射 | 对应前端现有页面、现有路由、现有展示区域、现有接口、现有数据表/集合、字段映射 |
| 数据规则 | 数据源、真实/模拟模式、主题、关键词、标签、分类、内容数量、更新时间、更新频率、排序权重 |
| 自动化规则 | 是否启用自动化、任务模板、执行时间、执行优先级、审核规则、推送规则、失败重试规则 |
| 运行状态 | 启用/暂停、待生成、待审核、待推送、推送中、已推送、推送失败、最后执行时间、最后推送时间 |
| 追溯记录 | 生成记录、审核记录、推送记录、失败原因、操作日志、数据版本、回滚版本 |

模块管理必须支持：搜索、筛选、分页、详情查看、新增、编辑、删除、批量编辑、批量启停、批量设置数据源、批量设置频率、批量运行自动化、批量推送、查看日志、导入与导出。

所有模块管理操作只影响后台数据生成、审核与推送流程，**不直接修改前端页面和功能**。

---

## C 类：自动化任务与数据生成

新增“自动化任务中心”。我点击“一键自动化”后，系统必须真正执行完整链路，不允许只弹出成功提示。

### C1. 自动化完整流程

```text
读取模块配置
→ 获取真实数据或生成模拟数据
→ 数据清洗与字段格式化
→ 去重与质量检查
→ 分类、打标签、排序
→ 生成文字、摘要、图文草稿或模拟图片数据
→ 保存至后台内容库
→ 进入审核队列
→ 审核通过
→ 按前端现有字段格式发布/推送
→ 记录推送结果、数据版本与日志
```

### C2. 自动化执行范围

自动化任务必须支持以下三种范围：

| 执行方式 | 功能要求 |
|---|---|
| 单模块执行 | 只对选中的一个前端数据模块生成、审核或推送数据。 |
| 分组执行 | 按首页、新闻、榜单、推荐、公告、下载等模块分组执行。 |
| 全站执行 | 按所有已启用模块的独立配置批量执行。 |

### C3. 自动化操作能力

后台必须具备：立即执行、定时执行、暂停、恢复、取消、重跑、失败重试、按失败项重跑、查看执行历史、查看每一步日志、查看结果预览、手动审核、批量审核、发布推送、撤回推送和版本回滚。

---

## D 类：前端数据推送要求

自动化生成的最终目的，是向前端推送数据；但推送方式必须与现有前端兼容，不能改前端。

1. 先识别每个前端模块当前使用的接口、数据库表、数据集合、缓存键或数据源。
2. 后台根据模块映射，将审核通过的数据写入前端当前正在读取的目标位置。
3. 推送数据必须严格保留前端需要的字段名称、字段类型、状态值、排序字段、分页格式、图片字段和时间格式。
4. 前端刷新、重新请求或按其原有刷新机制获取数据后，应自然读到新内容。
5. 后台必须验证每次推送是否成功，包括目标模块、推送条数、目标接口/数据表、数据版本、执行时间、成功状态、失败原因。
6. 推送失败时，不覆盖旧数据；保留失败记录并支持重试。
7. 每次推送前保留上一版本数据，支持一键撤回或回滚。

> 数据可以使用真实数据、模拟数据或 mock 数据；但模拟数据也必须按真实数据流程入库、审核、发布、推送、查询和回滚，不能只在页面上临时展示。

---

## E 类：每日内容差异化规则

前端不改动，但后台必须让每天推送的数据明显不同。不同模块不得简单复制同一批内容。

每个模块都必须独立配置：主题、关键词、数据源、内容数量、分类、标签、生成模板、发布时间、排序权重、推荐规则和去重范围。

| 模块类型 | 后台差异化要求 |
|---|---|
| 首页信息流 | 每日更新不同主题、时间范围和内容组合，避免重复标题。 |
| 栏目列表 | 按栏目独立分类、标签、关键词和排序规则生成数据。 |
| 榜单模块 | 根据独立权重、热度值、更新时间或模拟指标计算排序。 |
| 推荐模块 | 按模块独立主题、标签、优先级和内容池推送。 |
| 搜索数据 | 持续更新可搜索的数据记录、关键词和索引信息。 |
| 公告/下载模块 | 按后台配置生成不同状态、时间、排序和内容记录。 |

必须实现标题去重、正文去重、图片/素材去重、主题去重、跨模块重复控制和已推送内容避重。每日自动化运行后，要生成“本次新增、更新、跳过、重复、失败、已推送”的统计结果。

---

## F 类：图文生成速度优化

当前图文生成过程过慢，需要只改后台的生成与任务处理机制。

### F1. 异步任务化

点击生成后，页面必须立即创建任务并返回任务 ID，不能长时间停在“正在生成”。生成工作由后台任务队列异步执行；用户离开、刷新或重新进入页面后，仍能看到原任务的真实进度和结果。

### F2. 并发处理

批量生成 5 条、8 条或更多内容时，必须采用安全并发，而不是逐条串行生成。可并行的步骤，包括文本生成、模拟数据准备、图片/模拟图片准备、字段格式化、草稿保存，必须同时执行。

### F3. 性能能力

必须实现：任务队列、并发上限、排队机制、超时控制、限流、缓存复用、重复请求合并、失败重试、断点恢复、失败任务隔离、任务取消和旧任务清理。

### F4. 生成模式

| 模式 | 后台处理要求 |
|---|---|
| 快速草稿模式 | 优先生成文字、摘要、标签和可复用封面/模拟图片，快速进入审核。 |
| 高质量图文模式 | 生成更完整的图文数据、定制素材或更复杂的模拟内容，允许耗时更长。 |

### F5. 任务进度展示

每项生成任务必须展示：任务 ID、模块、任务总数、排队数、执行中数量、成功数、失败数、跳过数、当前步骤、单条耗时、总耗时、失败原因、重试次数、结果预览、审核状态和推送状态。

生成完成后必须自动进入审核队列；审核通过后必须自动或手动推送至对应前端现有数据位置。

在现有后台基础上，补齐以下可实际使用的功能；禁止空页面、只展示状态、无效菜单和无效按钮。

| 功能中心 | 必须补全的能力 |

| 仪表盘 | 模块数量、数据量、任务状态、待审核数、推送成功率、失败任务、生成耗时、最近操作、异常告警。 |
| 内容中心 | 草稿、待审核、已通过、已驳回、已发布、已归档、批量审核、审核意见、预览、版本记录、回滚。 |
| 数据管理 | 数据增删改查、搜索筛选、批量操作、导入导出、字段查看、来源记录、状态管理、数据版本。 |
| 数据源管理 | 真实/模拟数据源、字段映射、连接/测试、更新频率、数据源状态、权限标记、失败日志。 |
| 自动化任务中心 | 任务创建、任务模板、立即运行、定时计划、暂停恢复、取消、重试、日志、进度、结果、清理。 |
| 推送发布中心 | 待推送、推送中、推送成功、推送失败、目标模块、推送记录、数据版本、撤回、回滚。 |
| AI 管理 | 生成模板、提示词模板、生成参数、模型配置占位、调用记录、缓存、失败降级和耗时统计。 |
| 公告管理 | 新增、编辑、状态、排序、定时、归档、操作记录；仅管理后台数据，不改前端。 |
| 下载登记 | 下载文件管理、访问记录、状态、筛选、导出、审计日志。 |
| 系统监控 | 接口耗时、任务耗时、队列积压、缓存状态、错误日志、异常告警、系统健康状态。 |
| 用户与权限 | 用户、角色、菜单权限、接口权限、数据权限、登录日志、操作审计。 |
| 系统设置 | 数据保留周期、任务并发、缓存时间、模拟数据开关、备份、恢复和系统参数。 |

## H 类：禁止事项

以下情况一律视为未完成：

1. 修改了前端任何页面、功能、代码、接口契约或展示逻辑。
2. 后台生成的数据没有推送到前端现有数据读取位置。
3. 只做了后台页面或按钮，没有真实保存、生成、审核、推送、日志和回滚逻辑。
4. 所有模块使用同一批重复数据、相同标题、相同图片、相同排序或相同模板。
5. 图文任务仍然逐条串行执行，批量任务页面长时间卡死。
6. 任务刷新后丢失、失败无法定位、推送无法重试、数据无法回滚。
7. 出现空白菜单、假进度、假成功提示、静态状态或无实际操作结果的按钮。

## I 类：最终验收与交付

开发过程中不需要向我确认一般性技术问题，请自行完成全部改造、自测、修复和完善。只有以下项目全部满足后才能交付：

1. **前端零改动证明**：确认前端代码、页面、路由、功能、样式、文案、交互和接口契约均未修改。
2. **模块全量登记证明**：提供全部前端现有模块与后台模块台账的完整对应关系。
3. **自动化运行证明**：展示单模块、分组、全站三种自动化任务均可正常运行。
4. **前端数据推送证明**：展示后台自动化生成或模拟的数据已按前端原有字段和位置推送成功，前端无需改动即可读取最新数据。
5. **差异化证明**：展示至少连续 3 次自动化运行后，不同模块生成和推送的数据在主题、标题、内容、标签、排序或数量上存在明显差异。
6. **生成加速证明**：记录生成 1 条、5 条、8 条内容的耗时，证明批量任务使用异步并发处理，且单条失败不影响其他任务。
7. **后台完整性证明**：逐项测试所有菜单、按钮、筛选、批量操作、任务、审核、推送、日志、重试和回滚功能，清理全部无效功能。
8. **交付材料**：提交模块映射表、接口/数据表映射表、任务流程说明、任务日志、推送记录、性能对比结果、异常处理说明和完整自测结果。

**完成全部内容、自测通过并提供逐项证据后再交付；不要只完成一部分，也不要中途让我确认。**
