# 股市布局与 SEC 智能摘要设计

**设计原则：所有能力均追加于股市原工作区之后。原菜单、原面板、字段、顺序、路由和既有按钮不参与布局重排或摘要替换。**

## 账户级布局

布局只保存当前账户在“终端内股票研究工作台”中的卡片顺序与可见性，不保存行情、申报正文、图表数据或任何原面板状态。默认卡片为市场环境、代码观察、公开申报、公司事实和观察清单；用户可使用键盘或原生拖放调整顺序、切换显示、保存、恢复或恢复默认。每个账户仅有一份工作台布局，服务端按账户标识隔离。

## SEC 智能摘要

摘要只由已在服务器读取的 SEC 主文件文本生成。模型返回结构化的“文件要点、关键财务数据、风险提示、证据片段、风险/数据边界”，并对每一个要点保留来自原文的短证据片段。系统提示禁止模型推断市场影响、估值、评级、交易建议、未披露事实或法律结论；原文不可读、输出不可解析或证据不足时，终端显示真实不可用状态，不生成替代摘要。

| 字段 | 用途 | 边界 |
| --- | --- | --- |
| `headline` | 文件内容中立概述 | 不超过 220 字；不得含投资建议。 |
| `financialFacts` | 已披露的财务或经营事实 | 每项含期间、值/单位（如文本明确）和原文证据。 |
| `riskAlerts` | 文件明确披露的风险或不确定性 | 每项含类别和原文证据；不是风险评级或预测。 |
| `keyPoints` | 影响文件阅读的披露要点 | 仅复述来源文本；保留证据片段。 |
| `source` | CIK、文件编号、主文件、读取时点、正文长度 | 供终端内复核，不作为外部跳转。 |

模型调用在用户点击“生成终端内智能摘要”后才从服务器触发，使用本次实时模型目录中可用的 `gpt-5-mini` 与严格 JSON Schema；不在客户端暴露凭据，不后台批量调用。
