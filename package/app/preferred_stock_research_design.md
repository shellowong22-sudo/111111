# 优先股终端内深化设计

**设计原则：** 每项能力仅作为原优先股工作区之后的独立追加层呈现。公开披露、市场参照、筛选结果、输入研究和计算结果都留在本终端；不以外部网页跳转承载核心研究路径；缺少可再分发或可核验数据时明确显示真实空状态。

## 23 项差异化研究能力

| 原功能码 | 追加的终端内研究能力 | 主要依据或输入 | 终端产出与事实边界 |
| --- | --- | --- | --- |
| SECF | 发行主体与优先证券可识别性筛选 | SEC 主体、CIK、代码、申报目录 | 以名称、代码或 CIK 检索发行主体；仅显示公开申报可验证的识别信息，不伪造优先股全市场清单 |
| PSCH | 条款证据检索与原文片段核验 | SEC 表单目录与文件文本 | 按赎回、股息、转换、清算、浮动利率等关键词展示文件级片段；未能提取的条款保留为空 |
| WB | 利率—信用环境双曲线观察 | FRED 国债曲线、IG/评级级别 OAS、财政部曲线 | 将期限利率与指数级信用环境分层展示；不把指数 OAS 标为优先股个券利差 |
| WEI | 同发行主体股权关系与披露活跃度地图 | SEC 主体代码、SIC、申报日期 | 显示可验证的主体证券代码、行业分类和申报时间轴；没有授权股票价格时不生成股价或行业收益 |
| FIT | 执行前资料完备性闸门 | 用户输入的标识、方向、数量、目标、时点 | 返回可执行性资料缺口、需核验字段和终端审计记录；不发送订单、不生成交易成本或报价 |
| QFM | 公共因子可用性与环境敏感度面板 | FRED 历史序列与披露覆盖 | 显示利率、信用环境与事件覆盖的已读/不可读矩阵；不宣称因子收益、预测收益或回测表现 |
| EDS | SEC 披露事件雷达 | 8-K、424B、8-A、10-Q、10-K 等目录记录 | 按表单和期间筛选事件；只展示已实际读取的申报时间与表单，不推断市场冲击 |
| CMA | 多发行主体资料可比性矩阵 | 两至四个 CIK 的申报、标签和字段覆盖 | 比较申报新鲜度、条款关键词覆盖及数据缺口；不比较未经授权的收益率或估值 |
| POR | 用户输入的集中度与约束审阅 | 用户输入的研究权重、发行主体、上限 | 显示权重合计、主体集中度、缺失标识与约束偏离；为研究校验，不构成配置建议 |
| AIDE | 来源优先的证据缺口分诊 | 终端实际读取的披露、利率、信用参照状态 | 基于可读状态给出“已核验/待补证/不可读”证据清单；不生成未有来源支持的投资结论 |
| VIZ | 研究证据时间轴与环境联动图 | SEC 申报日期、FRED 时间序列 | 交互选择日期窗口，联动显示披露事件和公共环境观察；不构造事件因果或价格响应 |
| PORD | 当前—目标权重的再平衡偏离审阅 | 用户输入当前权重与目标权重 | 显示偏离、上限触发和未覆盖主体；只提供输入透明度与记录，不执行或推荐调仓 |
| RPA | 输入驱动的变动归因桥 | 用户输入期初、期末、现金分配与分类标签 | 将变化拆为市值、现金流、其他已标注类别；不以模拟回报补齐缺失数据 |
| AID | 分步研究准备度向导 | 发行识别、条款、环境、风险、流动性证据状态 | 给出下一条可核验的终端内研究步骤；不替代人工判断或自动推荐证券 |
| DAT | 字段溯源与读取新鲜度工作台 | 实际响应时点、延迟、来源标识 | 展示每类字段的机构、读取时间、频率与使用限制；读取延迟不等同市场更新时间 |
| MDL | 研究情景版本治理 | 用户输入情景参数与证据版本 | 记录场景名称、参数范围、创建时间和证据版本；不隐藏假设或声称预测能力 |
| APP | 账户级优先股证据包与审阅流 | 终端内保存的源链接、指纹、摘录与权限 | 支持草稿、提交、退回、批准、共享、版本差异和追加审计；不镜像第三方文件全文 |
| INF | 公共来源可用性与读取延迟监测 | SEC、FRED、财政部实际探测 | 显示可读/不可读、记录量和耗时；不以缓存样本或随机数据掩盖源端不可读 |
| PRC | 条款输入下的现金流与赎回敏感度场景 | 用户输入票面、面值、频率、赎回日及可选 FRED 参照 | 输出透明输入对应的现金流、累计分配、可赎回提示和参照利率；非实时报价或估值结论 |
| CRD | 发行主体披露证据与信用环境卡 | SEC Company Facts、申报目录、FRED OAS | 显示标准报表事实的报告期与信用环境参照；不输出个券评级、PD 或信用结论 |
| LIQ | 可交易性资料覆盖与人工报价完整性检查 | 授权状态、用户输入报价字段 | 清楚显示无授权逐笔成交时的真实空状态；如用户录入资料，仅做字段完整性与时点检查 |
| CASE | 可复现披露案例时间线 | 选定 CIK、已读表单和证据片段 | 生成可回看的真实披露案例时间线与缺口清单；不使用虚构公司或编造案例结果 |
| SOP | 五阶段终端内研究流程编排 | 上述功能的真实导航与状态 | 每一步可直接打开相应原入口/追加层，记录完成状态；不设置空链接或假工作流 |

## 追加层共用数据契约

所有公开快照返回 `asOf`、`sourceStatus`、`sourceLabel`、`latencyMs`、`limitation` 和明确的记录数。数据读取采用短缓存和并发合并；上游不可读时返回空集合与原因，不回退到演示样本。所有需要用户输入的研究卡片保留输入、输入时点与用途标识，避免将用户假设标为市场事实。

## 账户级证据包数据模型

`preferred_research_packages` 保存研究名称、主体名称、CIK、状态与审阅截止时间。`preferred_research_documents` 仅保存官方来源 URL、来源机构、文档类型、文档日期、SHA-256 指纹和受限长度的证据摘录，避免把外部全文复制进数据库。`preferred_research_shares`、`preferred_research_versions`、`preferred_research_reviews` 与 `preferred_research_audit_events` 分别承载成员权限、提交快照、审阅决定与追加式操作轨迹。

该设计只让 **APP** 承担跨成员协作与证据治理；其余 22 项分别聚焦于主体识别、条款、环境、比较、输入透明度、研究准备度、可视化、计算、来源和可交易性边界，避免将所有功能收敛为重复台账。
