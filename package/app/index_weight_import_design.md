# 指数事件详情与官方权重表导入设计

## 导入范围与来源约束

权重表以 CSV 在用户浏览器本地解析，终端只将经过服务端校验的结构化行、来源 URL、来源名称、文件名、表格生效日和来源指纹写入当前账户数据库；不会保存原始文件字节。导入 URL 必须使用 HTTPS，且域名必须为 `nasdaq.com` 或 `indexes.nasdaqomx.com`，否则不能标记为官方权重表。

CSV 必须包含 `ticker,name,weightPct` 三列。每个代码只能出现一次，权重须为大于 0 且不大于 100 的有限数，整表权重合计必须在 99.95% 至 100.05% 之间。导入日期由用户按官方表的发布日期/生效日填写，服务端以该日期与来源 URL 形成可审计批次。

## 事件实际影响的计算边界

每个成分变更事件只使用当前账户导入的官方权重批次，不向其他账户暴露任何导入数据。为了显示实际影响，终端要求同时找到：事件生效日的后置权重表（读取新增成分的权重），以及生效日前最近的前置权重表（读取移除成分的权重）。两张表都必须来自已校验的官方 URL，且前置表日期严格早于生效日。

终端展示新增权重、移除权重及其净差，并逐项显示各自使用的表格日期、来源和未匹配代码。只有全部相关代码能在相应官方表中找到时，影响状态才标记为“已核验”；否则不显示合成数值，并明确列出缺少的表或代码。不会用当前权重、ETF 持仓、等权、市场价格或第三方网页补足缺失字段。

## 权限、审计与详情

导入、导入列表和事件影响计算均为账户级受保护能力。每次导入会生成批次和审计记录，包含导入人、行数、日期、来源和内容指纹。公开事件详情模态框对所有终端用户展示官方公告中已归档的标题、日期、新增/移除名单、来源机构、读取日期和历史背景；账户级权重影响仅对导入该批次的账户展示。
